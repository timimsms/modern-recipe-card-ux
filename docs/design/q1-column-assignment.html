Finding Q1 · layout engine · phase 02

Row spans are determined. Column position is not.

A step spans exactly the rows it consumes — that part is forced. But when a one-step prep chain feeds a merge nine columns to the right, there are three defensible places to put it, and the original site uses different answers in different recipes. All three are rendered below from a single renderer, so column assignment is genuinely the only variable.

Verdict

Default to right-packed.

Not because it is prettier — because it is the only one of the three where column position means something. Under right-packed, a step's column is exactly its distance from the finished dish. Every cell in column 7 is one move from done, in every recipe, at every depth. That is what makes a shading ramp legible as "how close to done", which is precisely how Phase 02 defines PlacedCell.depth and how R5 proposes to encode grouping.

Under left-packed, column position means "how much prep has happened to the rawest thing in this cell" — a quantity that is measured from a different origin in every branch, and is therefore not comparable between two cells in the same column. A ramp painted across those columns would be decoration pretending to be structure.

Stretch-to-merge is better than expected, and that changes the recommendation.

PHASE-02 predicted that stretch would interact badly with bottom-right anchoring — that a stretched cell's text would "float far from its inputs". Rendered, the opposite is the case. The text does land at the right edge, but the body of the cell bridges the whole gap, so the butter row is visibly connected to the step that consumes it. It is the only one of the three where that long-range dependency is drawn rather than implied.

Its actual failure is weight, not position. A seven-column bar reads at nearly the weight of the prelude band, so the least important step on the chart becomes one of the most prominent things on it. That is a real disqualification — but the thing it was doing well is worth keeping, and the fix below keeps it.

The fix: right-packed geometry, with a leader rule across the gap.

Right-packed's only genuine cost is that the six blank columns give the eye nothing to follow. Stretch solved that by making the gap into a cell. A hairline through the filler solves it for the price of one CSS rule — turn on "Leader rules in the gaps" above and compare.

This matters beyond aesthetics: it is a rendering decision, so it costs the layout plan nothing and every track gets to make it independently. The alternative — a hybrid that stretches one-step chains — would push the same fix into GridPlan, where it would make column position mean "distance from done" for most cells and "a range of distances" for a few. Any depth-driven encoding would then need a special case forever, to serve exactly one cell in the entire corpus.

Ship right-packed, unconditionally. Keep all three implemented behind the columns option — they cost little and the golden files are more informative with three variants than one — but there is no hybrid heuristic and no per-branch rule.

The control case is the strongest evidence, because almost nothing happens in it.

Grilled artichokes renders with identical step geometry and identical width under all three strategies — 8 columns, same pixel width, every cell in the same place. The only difference the measurements can find is that right- and left-packed emit two filler cells where stretch emits none, and filler is invisible.

The strategies can only diverge where one branch is shorter than its sibling. In a pure chain there is no choice to make. So this decision costs nothing on simple recipes and everything on the ones the format exists for — and it cannot be validated on easy cases at all.

Unplanned finding: the stray-border complaint is partly a table artifact.

R1 — "the vertical border that extends from the prior instruction to the ones beneath" — is the most-cited complaint about the original. Turn on Reveal filler cells above and you can see why it exists: an HTML table has no way to say nothing is here. Every gap must be an actual <td>, every <td> draws borders, and CFE's righthide class is a hand-applied patch over that.

CSS Grid can leave a track genuinely empty. In all three renderings above the filler carries no border because it is not a box — it is unoccupied space. So the complaint that launched this project is, in part, an artifact of the 2004 substrate rather than of the format. That is evidence for Q3, which currently assumes tables might win on accessibility; whatever that test concludes, a table renderer has to re-solve a problem the grid does not have.
